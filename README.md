# Gamepad Socket

Gamepad Socket is a Windows command-line bridge for [DS5-Web-Audio-Haptics](https://github.com/rafaelvaloto/DS5-Web-Audio-Haptics). It receives the input generated by the web application over WebSocket and exposes it as a virtual gamepad through ViGEmBus.

This makes it possible to use the [DS5-Web-Audio-Haptics](https://github.com/rafaelvaloto/DS5-Web-Audio-Haptics) experience with games that do not support a DualSense controller over Bluetooth. The game sees a compatible virtual Xbox 360 or DualShock 4 controller while the web application handles the DualSense input and haptic/audio features.

> This project uses the free code signing provided by the [SignPath Foundation](https://about.signpath.io/foundation), backed by [SignPath.io](https://signpath.io/).

Gamepad Socket is a background service, not a standalone game or controller mapper: start it before connecting DS5-Web-Audio-Haptics.

## For users

### Download

Download the `.zip` package containing the executable from the Gamepad Socket release. Extract the package to a folder of your choice, then run `Gamepad_Socket.exe` from PowerShell or Command Prompt.

Before starting the server, install the [ViGEmBus driver](https://github.com/nefarius/ViGEmBus/releases/download/v1.22.0/ViGEmBus_1.22.0_x64_x86_arm64.exe).

Open PowerShell or Command Prompt, then run the executable with the controller type and TCP port you want to use:

```text
C:\path\to\Gamepad_Socket.exe --controller xbox --port 26760
C:\path\to\Gamepad_Socket.exe --controller ds4 --port 26760
```

`xbox` creates a virtual Xbox 360 controller and `ds4` creates a virtual DualShock 4
controller. If `--controller` is omitted, Xbox 360 is used. If `--port` is omitted,
the server listens on port `26760`.

Keep the console window open while using the virtual controller. The server accepts
WebSocket connections on all network interfaces; raw TCP connections are not
supported. Press `Ctrl+C` to stop it.

## Requirements

- Windows
- [ViGEmBus driver](https://github.com/nefarius/ViGEmBus/releases/download/v1.22.0/ViGEmBus_1.22.0_x64_x86_arm64.exe)

## For developers

### Building from source

The CMake project downloads and builds ViGEmClient automatically during
configuration. Internet access is required on the first configure.

```powershell
cmake -S . -B build
cmake --build build --config Release
```

The executable is generated at `build\Release\Gamepad_Socket.exe`.

### WebSocket Protocol

The client must connect using `ws://` and send the gamepad state as **Binary WebSocket frames** (`ArrayBuffer`). To ensure zero parsing overhead on the server, the payload must be exactly **12 bytes** long, mirroring the native `XUSB_REPORT` C++ structure in Little-Endian format.

#### Payload Structure (12 Bytes)

| Offset | Type        | Range              | Description               |
| :----- | :---------- | :----------------- | :------------------------ |
| `0x00` | `uint16_le` | `0` to `65535`     | Buttons bitmask           |
| `0x02` | `uint8`     | `0` to `255`       | Left Trigger              |
| `0x03` | `uint8`     | `0` to `255`       | Right Trigger             |
| `0x04` | `int16_le`  | `-32768` to `32767`| Left Analog X             |
| `0x06` | `int16_le`  | `-32768` to `32767`| Left Analog Y             |
| `0x08` | `int16_le`  | `-32768` to `32767`| Right Analog X            |
| `0x0A` | `int16_le`  | `-32768` to `32767`| Right Analog Y            |

#### Button Bitmask Mapping

Use bitwise OR (`|`) to combine multiple active buttons.

* `0x0001` - D-Pad Up
* `0x0002` - D-Pad Down
* `0x0004` - D-Pad Left
* `0x0008` - D-Pad Right
* `0x0010` - Start / Options
* `0x0020` - Back / Share
* `0x0040` - Left Stick Click (L3)
* `0x0080` - Right Stick Click (R3)
* `0x0100` - Left Bumper (L1)
* `0x0200` - Right Bumper (R1)
* `0x0400` - Guide / PS Button
* `0x1000` - A / Cross
* `0x2000` - B / Circle
* `0x4000` - X / Square
* `0x8000` - Y / Triangle

*Note: The server expects a continuous stream of the full state. State is not preserved between frames if fields are omitted, as the entire 12-byte buffer overwrites the current gamepad state.*

Supported fields:

- Buttons: `cross`, `circle`, `square`, `triangle` or `a`, `b`, `x`, `y`
- D-pad: `up`, `down`, `left`, `right`
- System: `start`, `share`, `ps`
- Shoulder/stick buttons: `lb`, `rb`, `ls`, `rs` or `l1`, `r1`, `l3`, `r3`
- Sticks: `lx`, `ly`, `rx`, `ry`, with values from `-1` to `1`
- Triggers: `lt`, `rt`, with values from `0` to `1`

Boolean values accept `0`, `1`, `false`, `true`, `off`, and `on`.
The input Y axis uses `+1` for up and is sent directly to the Xbox report.

## Logging

The console shows informational messages for server and connection status, and error
messages when initialization, networking, protocol, or virtual gamepad operations
fail. Normal input updates are not logged.
